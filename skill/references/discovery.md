# 产品发现与用户研究（Discovery）

发现阶段回答一个问题：**这个问题值得解决吗？** 绝大多数产品失败不是做得烂，而是做了没人要的东西。发现阶段花的每一天，都在给后面几个月的开发买保险。

## 1. Jobs to Be Done（JTBD）

核心思想：用户不是"购买产品"，而是"雇佣产品完成一项任务"。人们买电钻不是要电钻，是要墙上的洞——甚至不是要洞，是要挂上全家福后家的感觉。

**JTBD 陈述模板：**
> 当我 [处境/触发场景]，我想要 [动机]，以便 [期望结果]。
> 例：当我通勤路上有 40 分钟碎片时间（处境），我想要不费眼睛地获取信息（动机），以便到公司时不落后于行业动态（结果）。

**三层 Job：**

- 功能性（functional）：完成什么任务
- 情感性（emotional）：想有什么感受（安心、掌控感）
- 社会性（social）：想被别人怎么看（专业、有品位）

定价能力往往藏在情感和社会层——功能层最容易被抄。

**竞争视角：** 你的竞品是"用户现在雇佣什么来完成这个 job"，不限于同类产品。抖音的竞品是所有消磨时间的方式；协作文档的竞品可能是微信群 + 截图。

## 2. 用户访谈方法（The Mom Test 精髓）

差访谈获得礼貌性谎言，好访谈获得事实。三条铁律：

1. **聊他们的生活，不聊你的想法。** 不问"你会用这个功能吗"（对未来的承诺不可信），问"上次遇到这个问题是什么时候？你当时怎么解决的？"
2. **问具体过去，不问抽象未来。** "你多久跑一次步？"（回答会美化）→ "上周跑了几次？"（事实）。
3. **少说多听。** 你说得越多，数据污染越重。理想比例：你 20%，用户 80%。

**判断痛点真伪的信号强度（从强到弱）：**

1. 已经付费购买解决方案（最强）
2. 已经自己攒了个土办法（Excel、微信群、人肉流程）——黄金信号，说明痛到愿意付出劳动
3. 主动花时间寻找过解决方案
4. 能具体讲出最近一次发生的场景和损失
5. "对对对这是个问题"（几乎无价值）

**访谈规模参考：** 定性访谈 5-8 人/细分人群即可覆盖约 80% 的问题模式（Nielsen 曲线）；关键是按人群细分，而不是堆总数。

## 3. 需求真伪与需求分层

**需求过滤四问：**

1. 频率 × 强度：高频刚需（微信）、低频刚需（买房）、高频非刚需（可培养）、低频非刚需（放弃）
2. 谁付钱、谁使用、谁决策？（B 端三者常分离，C 端常合一）
3. 现有替代方案是什么？用户切换要放弃什么？
4. 这是止痛药（painkiller）还是维生素（vitamin）？维生素要靠习惯和情感建立粘性

**马斯洛式需求分层在产品上的应用（俞军框架补充）：**

- 用户价值 = 新体验 − 旧体验 − 切换成本。切换成本包括学习、数据迁移、关系链、习惯。这就是为什么"好 20%"的产品死掉：切换成本吃掉了差值。

## 4. Persona 与人群细分

Persona 的目的不是做一张好看的人物卡片，而是**让团队在争论时有共同的裁判**（"这个功能小美会用吗？"）。

有效 Persona 的要素：目标与动机、当前解决方案与不满、能力边界（技术水平、付费能力）、决策触发点。**无效要素：**年龄星座爱好等与产品决策无关的装饰性信息。

**细分优先级：** 先按"job 和使用场景"细分，再按行为细分，最后才按人口属性细分。同一个 job 下 25 岁和 45 岁用户的需求可能完全一致。

**Beachhead（滩头阵地）原则：** 早期产品选择一个窄而痛的细分人群打透（做到该人群的默认选择），再扩张。想同时服务所有人 = 谁也不觉得是为自己做的。

## 5. 机会评估（进入开发前的最后一道闸）

**机会评估文档（Marty Cagan 版，10 问精简为 6 问）：**

1. 解决什么问题？（问题陈述，一句话）
2. 为谁解决？（目标人群，越具体越好）
3. 市场多大 / 机会多大？（TAM 粗估即可，重点是量级）
4. 怎么衡量成功？（1 个北极星 + 2-3 个护栏指标）
5. 为什么是我们？为什么是现在？（能力匹配 + 时间窗口）
6. 不做会怎样？（机会成本视角，很多"好主意"在这一问下现形）

**验证阶梯（成本从低到高，能停早停）：**

1. 桌面研究 + 竞品分析（天级）
2. 用户访谈 5-8 个（周级）
3. 落地页 / 假门测试（fake door）：只做入口不做功能，测点击意愿
4. 人肉 MVP（Concierge / Wizard of Oz）：人工假装成产品跑通流程
5. 真 MVP：最小可用版本给真实用户

每一级只回答一个问题："值得进入下一级吗？" 直接跳到第 5 级 = 用最贵的方式验证假设。

## 6. 研究综合（从素材到洞察）

拿到一堆访谈记录/工单/反馈后：

1. **原子化**：拆成单条观察（一条 = 一个用户的一个具体行为或痛点，带出处）
2. **亲和图聚类**：按相似性聚类，命名主题——用"用户的问题"命名（"找不到历史订单"），不用"解决方案"命名（"需要搜索功能"）
3. **按 频率 × 严重度 × 战略相关性 排序主题**
4. 每个主题输出：证据条数、代表性原话、影响人群、建议下一步（继续研究 / 进方案 / 搁置）

注意区分：**反馈的响度 ≠ 问题的重要度。** 会哭的用户不一定代表沉默的大多数，用行为数据交叉验证。

## 7. 从零推演一个产品/功能的五步结构

适用于快速推演任何新产品或新功能的思考骨架（脑暴、方案初稿、老板突然问"XX 方向我们能做什么"时都用它）：

1. **破题**：目标是什么（增长/变现/留存/战略卡位）？约束是什么（平台、资源、时间窗口）？
2. **用户与场景**：细分人群 → 选定核心人群并给出理由 → 列出该人群的核心场景与痛点
3. **需求排序**：3-5 个候选需求，按痛点强度 × 频率排序，本次只解决 Top 1-2（其余显式放弃）
4. **方案设计**：核心流程 + 1-2 个能追溯到痛点分析的差异化设计点——不是功能清单
5. **衡量与验证**：1 个北极星贡献 + 2 个护栏指标，MVP 边界，下一步最小验证动作

这个结构的价值在于强制顺序：**不允许跳过 2、3 直接到 4**。多数平庸方案的病根都是从方案开始倒推用户。
