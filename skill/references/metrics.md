# 指标与实验（Metrics & Experimentation）

数据能力是头部 PM 与平庸 PM 差距最大的领域之一。核心不是会看数，而是**建立正确的指标体系 + 从数据到决策的严谨推理**。本文件讲指标的选取、分析与实验；**从 0 搭建指标体系、看板设计、埋点治理、商业分析见 data-system.md**。

## 0. 指标选取的标准（选任何指标前先过这五问）

1. **可行动吗？** 指标变化时团队知道该做什么。反例：品牌知名度（变了也不知道谁该干嘛）。
2. **领先还是滞后？** 营收、流失是滞后指标（看到时木已成舟）；使用深度、NPS、健康分是领先指标。**看板上滞后指标定目标，领先指标驱动日常动作**——只盯滞后指标的团队永远在救火。
3. **比率优先于绝对值。** 绝对值（总注册数）只会涨，掩盖恶化；比率（次周留存率、人均时长）暴露真实趋势。绝对值用于沟通规模，比率用于判断健康。
4. **能被操纵吗？怎么防？** 每个指标预演一遍"团队怎么作弊能把它做上去"（弹窗轰炸拉日活、误导性引导拉转化），把作弊路径用护栏指标堵住。
5. **是虚荣指标吗？** 累计下载量、页面浏览量、注册总数——只涨不跌、与用户价值脱钩、汇报好看但不指导决策的指标，识别后从决策看板上移除（可以留在 PR 稿里）。

补充两个高频区分：
- **北极星 vs KPI**：北极星是"我们信仰什么是价值"（稳定，一年内不换），KPI 是"这个周期考核什么"（随阶段变）。两者混用会导致战略漂移。
- **代理指标（proxy）要定期验证**：用"7 日内完成 3 次搜索"代理"用户激活"，每季度要回测这个代理和真实留存的相关性还在不在——产品变了，代理会失效。

## 1. 北极星指标（North Star Metric）

好北极星的标准：**同时反映用户价值和商业价值**，且团队能影响它。
- 反例：注册数（不反映价值）、营收（滞后且易短期操纵——涨价可以立刻拉高营收同时杀死产品）
- 正例：Spotify"收听总时长"、Airbnb"预订间夜数"、Slack"发送消息的活跃团队数"、B 端 SaaS 常用"周活跃使用核心功能的席位数"

**北极星分解树：** 北极星 = 若干输入指标的函数，把它拆到团队可直接干预的层级。
例：预订间夜数 = 访客数 × 搜索转化率 × 下单转化率 × 复购系数。每个团队认领 1-2 个输入指标。

护栏指标（guardrails）与北极星成对出现：追时长时看"卸载率/负反馈率"，追转化时看"退款率"。

## 2. 指标体系框架速查

- **AARRR 海盗模型**（增长视角）：获客 Acquisition → 激活 Activation → 留存 Retention → 收入 Revenue → 推荐 Referral。健康顺序是先 R（留存）后 A（获客）——漏桶不补，买量白买。
- **HEART**（体验视角，Google）：Happiness（满意度/NPS）、Engagement（参与深度）、Adoption（新功能采纳）、Retention（留存）、Task success（任务完成率/时长/出错率）。适合功能级评估。
- **B 端指标特有项**：NDR（净收入留存，>100% 是 SaaS 及格线，>120% 优秀）、LTV/CAC（>3 健康）、CAC 回收期（<12 月健康）、逻辑流失 vs 金额流失分开看、席位扩展率。

## 3. 留存分析（最重要的单一分析）

- **留存曲线怎么看**：X 轴为用户生命周期天数，按注册周分群（cohort）。曲线**变平**=有 PMF 的核心信号；持续下探到 0 = 尚无 PMF，先别做增长。
- **留存定义要贴 job 的自然频率**：外卖看周留存、记账看月留存、报税看年留存。给低频产品套日活指标是自欺。
- **Magic moment / Aha 时刻**：找到"完成后留存率显著跃升的早期行为"（经典案例：Facebook 早期发现"10 天内加 7 个好友"）。方法：对留存/流失用户做早期行为对比，找区分度最大的行为，再用产品设计推着新用户尽快完成它。注意这是相关性，要用实验验证因果。
- **流失分析**：区分"未激活流失"（没体验到价值）和"衰减流失"（价值不再）。前者修 onboarding，后者查竞品/需求变化。

## 4. 漏斗与归因

- 漏斗分析纪律：每步流失都要区分"体验问题"（能修）和"意愿筛选"（该流失的流失，修了反而放进低质量用户）。
- 转化率变化先查分母：转化率跌了经常不是产品变差，而是渠道放量拉低了流量质量。**任何比率指标异动，先拆分子分母，再按渠道/人群/版本/地区四刀切分。**
- 归因模型（末次点击/首次点击/线性/时间衰减）没有对错只有偏向，重要的是全团队用同一套且知道它偏向谁。

## 5. A/B 测试（实验设计与常见坑）

**实验设计清单：**
1. 假设先行：改动 X → 预期指标 Y 变化 Z%，因为 [机制]。没有机制假说的实验是抽签。
2. 样本量预估：用基线转化率 + 最小可检测效应（MDE）算，不够就延长时间或提高流量占比。日活几千的产品测 1% 的提升基本不可行——诚实告知，改用更大改动或定性方法。
3. 实验周期 ≥ 一个完整业务周期（含周末），且**不到预定样本量不偷看做决策**（偷看导致假阳性率飙升）。
4. 一次实验一个主指标；多指标时预先声明主次，防止事后"总有一个显著"。

**经典陷阱：**
- **新奇效应**：新功能头两周数据虚高，看长期留存分层
- **辛普森悖论**：总体涨、每个分群都在跌（结构变了），重要结论必须分群验证
- **溢出效应**：社交/双边产品实验组污染对照组（司机端实验影响整个城市运力），需按城市/集群随机化
- **幸存者偏差**：只统计留下来的用户
- **p 值黑客**：换指标、换时段、换人群直到显著。预注册假设是解药。

**显著但微小怎么办：** 统计显著 ≠ 值得上线。0.1% 的提升若伴随代码复杂度上升，可能是负资产。决策 = 统计显著 + 效应量 + 维护成本 + 战略方向四者合议。

## 6. 从数据到决策的推理纪律

- **相关不是因果。** 观察数据只配提出假设，因果结论要实验或至少准实验（双重差分、断点回归的直觉版：找自然对照组）。
- **指标异动排查 SOP**：先查数据管道（埋点坏了占异动原因的一半）→ 查外部事件（节假日、竞品动作、舆情）→ 查自身变更（发版、运营活动、策略调整）→ 四刀切分定位人群 → 提出机制假设 → 找证据。
- **Goodhart 定律**：指标一旦成为目标就会被玩坏。对抗方法：指标成对设置（数量+质量）、定期轮换审视口径、抽样人工看 case（数字后面是人，头部 PM 每周都亲自看原始 session/工单/弹幕）。
