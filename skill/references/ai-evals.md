# 模型与 Agent 评估（AI Evals）——前沿实验室的工法

站位：假设你是前沿实验室的评估负责人。核心认知：**评估体系就是 AI 产品的需求文档**。传统软件用 PRD 逐条定义行为，AI 产品做不到——评估集 + rubric 就是你的 PRD。谁定义了"什么算好"，谁就定义了产品。全文三部分：**上篇（一至七）是工法**——指标怎么定、数据集怎么建、判定器怎么校准；**下篇（八）是分类型知识库**——每类 AI 模型分别用什么方法、什么指标、什么思路；**附篇（九）是 Benchmark 解剖**——约 20 篇知名基准论文的造法、数字与教训；**附篇（十）是 Tech Report 解剖**——字节/腾讯/阿里/DeepSeek 等大厂技术报告的评估章节怎么做、怎么读；**附篇（十一）是公司系 Benchmark Report 解剖**——大厂为基准单独发布的报告（SuperGPQA/ArtifactsBench/VitaBench 等）的造法与读法；**压轴（十二）是五问模型**——从以上全部案例抽象出的做 bench/eval 的统一方法论。本文是 ai-products.md §3 的深度展开；线上产品指标见 metric-library.md §21。

## 一、三条铁律（先立哲学）

1. **Evals 是规格说明，不是考试。** 写不出评估标准 = 没想清楚产品要什么。评估负责人的第一件事不是跑分，是把模糊的产品要求（"回答要专业"）翻译成可测的维度（"引用的事实可溯源；超出知识范围时声明而非编造；语气符合 style guide 第 3 条"）。
2. **测你要的，不是好测的。** 最好测的（单轮准确率、关键词命中）往往不是产品要的（多轮把事办成、不闯祸）。指标一旦定错，整个团队会对着错误方向爬山——AI 产品里 Goodhart 是一等风险，因为 prompt 迭代和模型训练都在真实地对你的 eval 优化。
3. **错误分析优先于指标数字。** 分数告诉你有没有变好，只有读原始轨迹才知道为什么。**评估负责人每周亲自读 20-50 条 transcript，这是不可外包的活**——数错误比调 prompt 重要。

## 二、评价体系：四层指标结构

**1. 结果层（它做成了吗）**：任务成功率。判定方式按可信度排序：**程序化状态校验**（数据库里订单真的退了款、代码跑通了单测、文件 diff 符合预期）> 用户确认 > LLM 判官 > 模型自报。**Agent 的自报完成率必然虚高，永远不可作为口径——查世界，不查嘴。**

**2. 过程层（轨迹质量，诊断信息全在这）**：
- **步数效率**：实际步数 ÷ 参考最优步数；配无效循环/重复调用的冗余率。
- **工具调用正确率**：拆三个子项分别统计——选对工具、参数合法、正确使用返回结果。混成一个数就无法行动。
- **错误恢复率**：工具报错/环境异常后自愈完成任务的比例。"从不出错"和"错了能恢复"是两种能力，真实世界里后者更值钱——评估环境要故意注入故障来测它。
- **副作用率**：做了任务之外的破坏性动作（改了不该改的文件、发了不该发的消息、删了数据）。这是 agent 的安全底线指标，零容忍档。
- **终止判断**：过早放弃率与该停不停率分开统计。

**3. 体验层**：TTFT 与端到端时长（P50/P95）、单任务全成本（含重试与多步）、格式遵循率、被打断后的可控性。

**4. 安全层（发布否决项，不是权衡项）**：有害请求拦截率与良性请求误拒率**成对考核**（只考核一边，产品必然被推向极端）；prompt 注入下不执行注入指令的比例；有据场景的幻觉率。

**关键口径——pass@k vs pass^k**：pass@k（k 次尝试至少成功一次）测能力上限，适合 demo；**pass^k（k 次全部成功）测可靠性，才是产品口径**——用户不会重试八次。τ-bench 暴露的普遍现象：很多模型 pass@1 尚可、pass^8 腰斩，行为方差大——这就是"demo 惊艳、日用拉胯"的数学解释。同题多跑的方差要单独列为可靠性指标。

## 三、数据集构造：分布 > 数量

**1. 先建任务分类学，再采样。** 维度：任务类型 × 难度 × 用户画像 × 风险等级。配额按真实流量分布，高风险尾部超采样。没有分类学的 eval 集是"手边有什么测什么"，分数不代表任何总体。

**2. 五个来源各司其职**：
- **生产流量脱敏采样**——分布的金标准；
- **失败回流**——每个线上事故、差评、人工纠正都变成永久回归用例，**eval 集是活的**；
- **专家构造**——覆盖能力边界，今天做不出的题留着丈量进步；
- **合成数据**——LLM 生成 + 人工验收，用于扩量和危险场景；注意合成题会偏向生成模型觉得"合理"的分布，需人工掺入怪题；
- **公开 benchmark**——只做外部坐标，不做发布依据。SWE-bench 需要出 Verified 版（人工复核砍掉题意含糊/测试有误的题）这件事本身就说明：**公开集里有相当比例的坏题，用前先人工抽 30 题看质量**。

**3. 四个集合分层**：冒烟集（几十条，分钟级，每次改动必跑）｜回归集（数百条，发版必跑）｜挑战集（当前过不了的硬题，看进步曲线）｜**金丝雀集**（从不公开、从不接触训练数据，专测污染——分数突然异常升高先怀疑泄漏，不是庆祝）。

**4. 标注质量**：rubric 写到**两个陌生标注员打分一致**才算可执行；分歧样本不是噪声，是 rubric 的 bug——逐条裁决并回写规则。Golden set 由最懂产品的人亲自标，这是 PM 不可外包的部分。

**5. 规模与统计直觉**：每个重要维度 50-200 条就能出信号，小而准 > 大而脏；**几百条样本上 2-3 个点的差异大概率是噪声**——比版本先算显著性，别为噪声开庆功会或问责会。

**6. 数据集卫生**：版本化（集合变了分数不可比，报分必须带集合版本号）；定期换血（一套集用太久，你优化的不再是能力而是这套题）；train/eval 严格隔离。

## 四、判定器：三档 + 校准纪律

- **程序化断言**：最硬最便宜，能用尽用（精确匹配、单测、状态校验、格式校验）。
- **LLM-as-judge**：用于主观维度，但判官要先过资格考——**与人工标注一致率到 80-90% 才可信**，按维度分别校准。三个已知偏差主动去偏：偏爱长回答（rubric 显式声明忽略长度）、位置偏差（pairwise 交换顺序跑两遍取交集）、自我偏好（判官换另一家的模型）。rubric 分维度打分（正确性/完整性/风格分开），单一总分掩盖 trade-off。
- **人工评审**：最贵，用于校准前两档和高风险决策。**pairwise 胜率比绝对打分稳**——人对"哪个更好"的一致性远高于"打几分"。
- 判定器本身要有回归测试：换判官模型等于换尺子，历史基线全部重算。

## 五、错误分析：最高 ROI 的活动

流程：抽样失败轨迹 → 开放式归类（先别套现成分类，让类别从数据里长出来）→ 形成错误分类学（agent 常见五类：**规划错、工具选择错、参数错、结果解读错、终止判断错**）→ 按频率 × 严重度排序 → 每类建最小复现集 → 修复后并入回归集。

定位轨迹失败用**第一分歧点（first divergence）**：从头找第一个偏离合理路径的步骤——后面的错误多是级联，修第一个。

免费标注要捡干净：用户的重试、改写、放弃、手动纠正都是天然负标注，全部回流。

## 六、发布决策规则（指标怎么用）

- **门槛结构**：主指标 ≥ 基线；安全与副作用指标零回归（否决项）；成本延迟在预算内——三者都过才进灰度。
- **新模型接入 SOP**：全量回归 + 挑战集 + **人工抽读 50 条 diff**。总分持平时行为可能已大变（风格、拒答边界、工具偏好），分数相同 ≠ 产品相同。
- **在线-离线闭环**：离线涨 → 灰度看在线指标（采纳率、修正率、重试率）→ 背离时先怀疑 eval 集分布过时，回流最新流量重建。离线分是代理，在线北极星才是真相。
- **成本-质量运营点**：每类任务在（质量、延迟、成本）三维上单独选运营点——客服摘要和法律审查不该用同一配置；降本省下的毛利要和质量下降造成的流失放同一张账上算。

## 七、小团队的最小可行版（没有实验室资源也要有的底线）

50 条冒烟集今天就建；每个 bad case 进集（一周后你就有活的回归集）；每周固定一小时读 20 条真实轨迹；改任何 prompt 前先跑冒烟集。这四件事成本近乎零，是"盲飞"与"有仪表"的分界线。

## 八、分类型评估知识库（各类 AI 模型：方法 × 指标 × 思路）

**总纲——选评估方法只问一个问题：这类输出的"对"有多可判？** 判定难度光谱五段，任何新模型类型先定位在哪一段，方法自动跟着定：①唯一答案、可执行可匹配 → 程序化判定；②有参考答案但表述自由 → 参考对比（学习型指标/judge 对照参考）；③无参考、质量主观 → 相对比较（pairwise/Arena/分维度 judge）；④多步改变世界 → 终态校验 + 轨迹；⑤概率/排序输出 → AUC/NDCG/校准。每条 = `方法｜指标｜代表基准｜思路与坑`。

### 组 A：可程序化判定（光谱①⑤）

- **代码生成**｜执行单元测试｜pass@1/pass@k、（产品口径）pass^k｜HumanEval/MBPP（已饱和）→ SWE-bench Verified（真实 repo 级）、LiveCodeBench（滚动出新题防污染）｜判定用执行不用文本相似；污染重灾区——只信出题时间晚于训练截止的题；函数级和 repo 级是两个世界，函数级高分外推不到工程能力。
- **数学 / 推理**｜最终答案程序化核对 + 过程单独评｜答案正确率；"答案对但过程错"的比例｜GSM8K（饱和）、MATH、AIME 逐年新题｜结果可验但过程不可靠——高风险场景（金融/医疗计算）要验过程；换一年新题分数掉多少，就是污染程度的体检；多次采样投票（自一致性）可提分，但产品里等于 k 倍成本。
- **结构化抽取（NER/JSON/表格）**｜精确匹配 + schema 校验｜实体级 F1（严格与部分匹配分开报）、schema 合规率｜-｜百分百可程序化，别浪费 judge；错误要分"抽错了"和"格式坏了"两类，修法完全不同。
- **分类 / 审核 / 风控判别**｜混淆矩阵体系｜Precision/Recall/F1、AUC-ROC（平衡时）、**PR-AUC（不平衡时）**、校准误差 ECE｜-｜类别 99:1 时 accuracy 无意义；**阈值不是技术参数是业务决策**——由误杀与漏放的业务成本反解（审核场景两类错误成本极不对称）；校准好的分数才能当概率用于分层处置（高分自动处置、中分人审）。

### 组 B：有参考答案、表述自由（光谱②）

- **机器翻译**｜n-gram 对比 → 学习型指标｜BLEU/chrF（旧）、COMET（与人评相关性显著更高）；人工用 MQM 错误分类｜WMT 系列｜n-gram 指标对 LLM 的意译系统性低估——新项目直接上学习型指标 + 抽样人评；术语一致性（domain 词表命中）要单独测。
- **摘要**｜LLM judge 分维度 + 事实核查｜忠实度（不编造）、覆盖度（要点全）、简洁度分开打分；QA 式评估（从原文出题，看摘要能否答上）｜-｜**ROUGE 与人判弱相关，基本失效**；LLM 的流畅度早已过关，错的全在事实——忠实度权重最高；长文摘要单独测（中段信息丢失）。
- **语音识别（ASR）**｜与转写金标对比｜WER（英文）/CER（中文）｜-｜大盘 WER 掩盖垂直灾难——按口音/噪声/专有名词分域测；热词与专名单独建集（产品投诉多数来自人名地名商品名）。

### 组 C：无参考、质量主观（光谱③）

- **开放对话 / 写作（通用 LLM）**｜相对比较为主｜pairwise 胜率、Arena Elo；指令遵循用可程序化拆项（IFEval 式：字数/格式/禁用词逐条断言）；多轮一致性｜Chatbot Arena、MT-Bench、IFEval｜绝对打分不稳，相对比较才稳；Arena 有分布偏差（重度用户+偏短对话），只当外部坐标；**风格与正确性分开评，否则模型学会"说得漂亮"**。
- **图像生成**｜人评为主、自动指标做回归警报｜维度拆：prompt 遵循/保真/美学/多样性；自动：FID（分布距离）、CLIPScore（图文对齐）——与人感相关弱｜DrawBench、PartiPrompts、生图 Arena｜发布判断靠盲测人评；已知弱点（文字渲染、手部、计数）单独建专项集追踪。
- **语音合成（TTS）**｜主观面板 + 自动代理｜MOS（自然度/相似度）；ASR 回环 WER 测可懂度（程序化）｜-｜MOS 面板贵——小样本人评做校准锚，自动代理跑日常回归；情感/多音字/中英混读单独测。
- **视频生成**｜维度化人评｜时序一致性、物理合理性、主体保持、prompt 遵循｜VBench 类维度基准｜比图像更缺可靠自动指标；抽帧评图像质量会漏掉时序问题（闪烁、变形）。

### 组 D：复合系统（光谱④）

- **RAG / 检索问答**｜**拆两段分别评**｜检索侧：recall@k、MRR、NDCG（用金标 chunk 集）；生成侧：忠实度/答案相关性/上下文相关性三元组 + 引用准确率｜RAGAS 类框架｜**端到端差先拆段归因——多数"模型不行"其实是检索不行**；忠实度是 LLM judge 最可靠的场景（有据可查）；"该拒答时拒答"（检索无结果仍硬答）单独统计。
- **Agent / 工具调用**｜终态校验 + 轨迹分析（见上篇二、五）｜任务完成率（查环境终态）、pass^k、工具调用三子项、错误恢复率、副作用率｜τ-bench（用户模拟+策略遵循）、WebArena/OSWorld（真实 web/桌面）、GAIA（多步推理检索）、SWE-bench（repo 修复）｜可复位沙箱是前提（determinstic replay）；策略遵循类任务（客服退款规则）单独评"守规矩"——能力强但不守规矩在 B 端是零分。
- **Embedding / 检索模型**｜下游任务代理评估｜recall@k、NDCG、聚类/分类下游分数｜MTEB｜通用榜和你的领域相关性可能很低——**用自有 query-doc 对建 200 条金标集，比看榜有用十倍**；难负例（hard negatives）质量决定评估区分度。
- **推荐 / 排序模型**｜离线初筛 + 在线定论｜离线 AUC/NDCG；在线 CTR/时长/留存（见 metric-library §24）｜-｜离线在线背离是常态（位置偏差、反馈回路）——离线只做初筛，决策靠实验。
- **奖励模型（RM）**｜与人偏好一致率｜偏好准确率、分维度一致率｜RewardBench 类｜**RM 是所有下游对齐的尺子——尺子歪，RLHF 全歪**；RM 被钻空子（reward hacking）的监控方式：定期人工抽查"高分但可疑"样本；RM 分数漂移要像口径变更一样管理。

### 组 E：横切专项（所有类型都要过）

- **安全**｜双向对抗测试｜有害拦截率 + 良性误拒率**成对**（XSTest 式良性对照集）；越狱成功率（红队+自动攻击）；偏见（模板替换后输出质量应一致，BBQ 式）；真实性（TruthfulQA 类）｜每版必测——安全分随能力提升会"自然"漂移，不是设一次就完。
- **长上下文**｜三档分测｜检索型（大海捞针及多针变体）、综合型（跨段汇总）、推理型（RULER 类）；位置效应（lost in the middle）｜**大海捞针满分只说明检索召回行，≠长文推理行**；报"有效上下文长度"（性能不塌的长度）而非标称长度。
- **幻觉与校准**｜分场景测｜有据场景：核对率；无据场景：**承认不知道率**（答对率 vs 尝试率双轴，SimpleQA 式）｜"该说不知道时说不知道"是独立能力，单独测——很多模型有据场景幻觉率低，但无据场景永不认怂。
- **多语言 / 本地化**｜按语言分层｜各语言分数单独报；翻译腔检测；低资源语言专项集｜英文分数不能外推；中文场景要测成语、网络语、简繁、中英混杂——这些在英文主导的公开基准里全是盲区。
- **微调 / 垂直模型**｜delta 评估｜领域集提升幅度 + **通用能力回归（灾难性遗忘检测）**放同一张表｜只报领域涨幅是自欺——垂直微调最常见的隐性代价是通用能力和安全对齐的退化，两边都要测。

## 九、Benchmark 解剖：知名基准是怎么造出来的（论文方法论精读）

来自约 20 篇基准论文（HumanEval、SWE-bench/Verified、τ-bench、WebArena、OSWorld、Terminal-Bench、MMLU/Redux、GPQA、GAIA、SimpleQA、BrowseComp、HLE、FrontierMath、MT-Bench、Chatbot Arena、IFEval、HELM、HealthBench、GDPval 及 Anthropic 评估实践）方法论章节的提炼。先看共同的设计模式，再查单个基准的造法速写。

### 九.1 十个构造设计模式（跨论文共性）

1. **判分押注执行与终态，判分器要"笨而硬"**。代码跑单测（HumanEval 平均每题 7.7 个）、repo 修复跑 fail-to-pass 测试（SWE-bench）、agent 比数据库终态（τ-bench）、web 任务查后端状态（WebArena）、终端任务验容器终态（Terminal-Bench）——能程序化判的一律不用 judge。LLM judge 只出现在语义等价比对这类边缘。
2. **Oracle 先行**：先证明"标准解能通过判分器"，再收题。SWE-bench 拿原 PR 当天然 oracle；Terminal-Bench 强制 oracle 解过 CI；τ-bench 对每题跑 40+ 次试验、迭代改写到终态唯一才冻结。你自建评估集也一样：判分器认不出正解的题，测出来全是噪声。
3. **真实来源必配陡峭漏斗**：SWE-bench 从 90,000 个 PR 过滤到 2,294 题（产出率 2.5%），Verified 再请 93 位工程师人工复核砍掉 68.3% 留 500 题；HLE 从 70,000+ 提交筛到 2,500。要么接受 <5% 的产出率，要么放弃真实来源全手写（HumanEval 164 题、GPQA、SimpleQA 全部原创）。
4. **答案唯一性靠"独立盲复答一致"近似保证**：GAIA 每题 2 名新标注员独立作答、三答案一致才收（因此删掉 32% 的题）；SimpleQA 第二名 trainer 盲答；GPQA 用"2 专家 + 3 个带搜索引擎的非专家"对抗验证。**即便如此，残余错误率 3%-10% 是常态**（SimpleQA ~3%、GPQA Diamond ~8%、FrontierMath ~7-10%、MMLU 6.5%、HLE 生化题 18-29% 存疑）——零错题不存在，所以发布后滚动纠错（bug bounty、Redux、Rolling 版）成了标配。
5. **对抗式收题是标配、但有系统性毒副作用**："当前最强模型答错才收题"（SimpleQA/BrowseComp/HLE 的门槛）会**富集错题**——模型答对的错题被过滤掉、模型答错的错题被留下来。HLE 生化题约 29% 与文献矛盾就是这么来的。解法：对抗筛之后必须再做一轮与模型无关的正向专家复核。
6. **专家经济学**：从爬公开题库（MMLU，零成本，6.5% 错题率）进化到付费专家原创（GPQA 时薪约 $95、HLE 单题最高 $5,000、GDPval 每任务专家耗时 6.7 小时/估值 $361）——单题成本上升 3-4 个数量级，买的是新颖性、防污染和答案质量。质量与成本没有第三条路。
7. **防污染三板斧，且作者们都承认不彻底**：私有保留集（GAIA 300 题答案不公开、HLE 双保留集）；canary 字符串 + 加密分发 + 请求勿明文转载（BrowseComp、GPQA、Terminal-Bench）；时间切割与滚动出新（只收训练截止后的 issue、LiveCodeBench 滚动出题、Terminal-Bench 1.0 饱和后重制 2.0）。
8. **可靠性与反作弊显式化**：pass^k 度量"稳定做对"（gpt-4o 在 τ-bench retail pass^1=61.2% 但 pass^8<25%）；每个组合至少重复 5 次跑；**故意放"不可行任务"**测 agent 会不会诚实说做不到（OSWorld 里 agent 在这类题只有 16.7%）；Terminal-Bench 甚至专门养了一个对抗 exploit agent 找作弊捷径。
9. **Judge 的资格线是"人-人一致率"，不是 100%**：MT-Bench 里 GPT-4 judge 与人一致 85%，而人与人只有 81%——judge ≥ 人-人即算合格；HealthBench 的 grader F1 落在医生互评区间内才敢用；GDPval 自动 grader 66% vs 人-人 71%，差 5 个点就被官方定性为"尚不能替代专家"。偏差要先量化再机制性去偏：位置偏差换序跑两遍取交集；冗长/格式偏差做成回归协变量（Arena 的 style control 上线后 GPT-4o-mini 从第 6 跌到 11——排行榜一半是文风）。
10. **Benchmark 本身也要被评估**：用 separability（95% 置信区间下能区分多少对模型）——MT-Bench 只有 22.6%、Arena-Hard 87.4%，前者因此被淘汰。你的内部评估集同理：区分不开两个版本的集合等于没有。另一课是治理：FrontierMath 由 OpenAI 出资且可见绝大部分题面、事后才披露——评估的利益冲突必须提前声明，否则分数的公信力一夜归零。

### 九.2 单基准造法速写（方法 memo）

- **HumanEval**：164 题全部手写防泄漏；pass@k 用无偏估计公式（朴素算法系统性低估）；证明了 BLEU 分不出代码对错，确立执行判分范式。
- **SWE-bench → Verified**：真实 repo + fail-to-pass 测试；Verified 的教训是**原基准系统性低估模型**——38% 题目描述欠规范、61% 单测过度特化，去噪后 GPT-4o 成绩翻倍（16%→33%）。分数异常先怀疑题坏，不是模型菜。
- **τ-bench**：全合成域（防污染）+ GPT-4 扮演用户 + 数据库终态判分 + pass^k；策略遵循靠终态间接验证。
- **WebArena / OSWorld**：自托管可复位环境；判分写成状态断言（查数据库/文件，不看 agent 说什么）；OSWorld 9 人 1800 小时里 400 小时花在 QA 复查——环境类基准四分之一成本在质检。
- **Terminal-Bench**：众包 229 题过三关验收（终态特异性/oracle 可解性/无作弊捷径）只留 39%；七步审核流水线含 exploit agent；作者自估一年内饱和——饱和是宿命，设计时就规划下一版。
- **MMLU → Redux**：爬题零验证的代价——全库 6.5% 错题、病毒学子集 57% 有问题，纠错后模型排名都变了。用任何公开集前先抽 30 题人工看质量。
- **GPQA**：构造工艺标杆——专家出题 → 专家验证 → 修订 → 再验证 → 3 名跨域博士带搜索引擎作答仍只对 34%（"Google-proof"的操作化定义）；按质量发奖金（专家答对+非专家答错才触发）。
- **GAIA**：题目设计三原则——真实世界、答案唯一且不随时间变、答案不以明文存在于网上；quasi-exact match 判分靠强制答案格式。
- **SimpleQA / BrowseComp**：单一可验证事实 + attempted vs correct 双轴（把"答错"和"没答"分开，测认怂能力）；BrowseComp 的"从答案反向造题"——先选事实再叠约束，天然保证可验证。
- **HLE**：全球征题 + $50 万奖金 + 模型对抗筛选 + 两轮专家评审；教训见上文第 5 条（评审限时 5 分钟不验全解 → 生化题 29% 存疑）。
- **FrontierMath**：数学家原创未发表题 + "guessproof"（蒙对概率 <1%）+ SymPy 自动验证；教训在治理不在工艺。
- **MT-Bench / LLM-as-judge 论文**：judge 三大偏差全部量化（位置：GPT-4 换序一致性仅 65%；冗长：GPT-3.5 被"重复注水"攻击骗过率 91%；自我偏好 +10-25%）；缓解手段有效性也量化（few-shot 65→77.5%、参考引导判数学 70%→15% 错误率）。
- **Chatbot Arena**：Bradley-Terry 聚合 + sandwich 标准误 + 按"缩小置信区间的贡献"主动分配对战；刷票用可交换性检验抓。《Leaderboard Illusion》的批评：大厂私测 27 个变体择优披露——公开榜可以被流程博弈，不只是被模型博弈。
- **IFEval**：只评"可程序验证"的指令切片（25 类）；strict/loose 双轨判分用来夹住真实水平——承认单一判分必有偏，就报一对上下界。
- **HELM**：scenario × 7 指标矩阵（准确率之外强制同报校准/鲁棒/公平/毒性/效率），显式声明哪些格子是空的——"设计上即不完整"是诚实，不是缺陷。
- **HealthBench**：262 名医生逐例写 rubric（共 48,562 条、每条带正负分值），GPT-4.1 逐条判——**专家条目化 + 廉价自动化**的两级架构，是主观质量规模化评估的当前最优解。
- **GDPval**：真实职业交付物 + 专家盲评 pairwise；价值在于把"AI 能力"锚到经济价值（44 个职业、$3T 工资盘子）——评估集的选题本身就是商业叙事。

### 九.3 自建 benchmark 的迁移清单（从论文里抄的作业）

1. 判分能程序化就程序化，判"世界的状态"不判"模型的话"；oracle 解先过判分器再收题。
2. 每题独立盲复答验证唯一性；预算 3-10% 残余错误率，开纠错通道，别宣称零错题。
3. 用了对抗式收题（模型答错才收），就必须再做一轮与模型无关的正向复核，否则你在富集错题。
4. 报分数必须带：集合版本号、重复次数、置信区间；比较两版先算 separability——区分不开就加题或换题。
5. 故意埋不可行任务和作弊捷径探测，测诚实和钻空子。
6. 公开可复现与抗污染不可兼得——想清楚你的评估集哪部分公开、哪部分保留、canary 放哪。
7. 饱和是宿命：设计时就写好"下一版从哪来"（滚动来源/难度储备）；以及利益冲突提前披露，公信力只能丢一次。

## 十、Tech Report 解剖：大厂技术报告的评估章节怎么做

材料来自模型技术报告的评估与数据章节：字节 Seed-Thinking-v1.5 / Doubao-1.5 / Seed-Coder / UI-TARS-2、腾讯 Hunyuan-Large、阿里 Qwen2.5 / Qwen3、DeepSeek-R1，及 GPT-4 / Llama 3 作对照。看的不是分数，是**他们怎么设计"证明自己"这件事**。

### 十.1 评估章节的通用骨架（七个部件）

①base 与 post-train 分开评（base 用 few-shot 公开集：MMLU/BBH/数学/代码；post-train 用对齐与领域集：IFEval、Arena-Hard、AIME、LiveCodeBench、BFCL）；②按能力维度组表（知识/推理/数学/代码/多语言/长文本/agent/安全），不按数据集堆砌；③公开集保可比 + in-house 集补"贴近真实用户"的短板；④主观能力用人评或 arena 类对战；⑤判分口径写进脚注（shots、CoT、采样参数、judge 模型、pass@k 的 k 与平均方式）；⑥防污染/数据独立性声明；⑦安全评估单列。

### 十.2 各家风格速写

- **字节 Seed**：把判分器当模型来迭代——自研 Seed-Verifier → Seed-Thinking-Verifier（人工标注测集上 82.7%→**99.3%**），专治 reward hacking。反饱和自建：AIME 年产 30 题方差太大 → 专家结构性改编出 100 道 **BeyondAIME**（答案不得是题面里的平凡数值，压猜对率）；代码用**最近 12 场 Codeforces 真题**报 pass@8（新题天然防污染；pass@8 比 Elo 估计稳）。训练数据侧"消灭猜测空间"：多选改填空、答案整数化、worst-of-N 全对的过易题删除；Doubao-1.5 声明"未使用任何其他模型生成的数据"。配套的自建基准工厂同样工业化：SuperGPQA 用 80+ 博士专家把守题源 + 名校众包转录 + 7 个模型当质检员（教训：让众包直接出题只有 37% 可用），选项扩到平均 9.67 个压猜对率；Multi-SWE-bench 68 名外包标注 + 14 名内部工程师验收（80% 准确率红线）、Docker 三态日志只认 fail2pass。
- **腾讯混元**：公开集大满贯之外单列 "**In-House Evaluation**" 一节——承认公开长文本集不贴用户，自建 PenguinScrolls（1,316 条：书籍/财报/法律文书，最长 128K，GPT-4o 判分）。路径是"内部集补测 → 成熟后开源成公共基准"（PenguinScrolls、ArtifactsBench、C3-Bench 都这么走）；但报告缺系统性去污染声明。
- **阿里 Qwen**：Qwen2.5 有全行业最明确的**量化去污染准则**——训练序列与任一测试序列的 token 级最长公共子序列 ≥13 且 ≥0.6× 较短序列长度，即从训练数据删除；另有不开源的中英双语 in-house 集。到 Qwen3 这一章节明显弱化——竞争加剧后披露透明度收缩，是行业普遍趋势（读报告时要意识到：没写 ≠ 没做，但也 ≠ 做了）。
- **DeepSeek**：R1 报告把采样口径写死——数学类 pass@1 用温度采样（0.6）生成 **64 个回答取平均**，因为单次贪心解码的方差大到能翻转结论；开放生成用 GPT-4-Turbo 当 judge，且用**长度控制**的 AlpacaEval 口径防冗长偏差。
- **西方对照一句**：GPT-4 报告用子串匹配查污染并**同时报告去污染前后两个分数**；Llama 3 按 n-gram 重叠把基准拆 clean/full 双列。"报两个数"比"声称自己干净"诚实一个量级。
- **方法论教训（GPT-Fathom，字节 2023）**：直接引用别家论文分数 = 口径不齐的 cherry-picking 温床——换个 prompt 模板，Llama 2-70B 的 TriviaQA 从 74.0 掉到 55.5；版本升级有**跷跷板现象**（gpt-3.5 升级后 HumanEval 涨到 80、MATH 从 32 掉到 15）。所以可信的报告要么同一 harness 复测所有对比对象，要么给能力回归表。

### 十.3 读报告的高信号清单（先看这些，再看分数）

1. **口径脚注完整度**：shots / CoT / 温度 / k 值与平均方式 / judge 是谁 / 集合版本——脚注越含糊，数字越不可比。
2. **对比列里缺了谁**：对比对象的挑选本身就是信息。
3. **in-house 集只能自证趋势**：不开源、不可复测，跨报告比较无效。
4. **防污染是否量化**：Qwen2.5 式准则或 GPT-4 式双列分数，还是一句"我们做了去重"带过。
5. **高方差基准是否多次采样平均**：AIME 这类 30 题的集合，只报单次的数字当噪声处理。
6. **有没有能力回归**：只报涨的维度是报喜文；跷跷板是常态，敢报跌的报告才可信。
7. **自建基准入表**：运动员兼裁判——看它是否开源可复测、是否报与人类偏好的一致率（ArtifactsBench 用"与 WebDev Arena 排名一致 94.4%"给自动裁判背书，是标准自证动作）。

### 十.4 报告之外的两个现实（国内语境）

- **自建基准 = 产品线铺路 + 成绩单**：Multi-SWE-bench 连着 RL 数据生产线，ArtifactsBench 连着前端代码卖点，WebWalkerQA 连着搜索 agent 产品线。看到大厂发新基准，先问"这在给哪条产品线铺路"。
- **国内双轨制**：能力榜单（司南 OpenCompass、SuperCLUE）是营销与初筛参考，无强制力且有泄题刷榜争议；**信通院备案安全评估才是硬约束**——关键词库 ≥1 万、安全题库 ≥2,000、应拒答率 ≥95%、误拒率 ≤5%，不过不能上线。发版排期要给备案评测留提前量；对外宣传引榜单，对内选型自建贴业务的私有评测集。

## 十一、公司系 Benchmark Report 解剖（大厂为基准单独发布的报告）

大厂造 benchmark 不是学术公益，动机通常四种：①给自家模型/产品线立靶子和成绩单；②基准与训练数据生产线同源（评测环境即 RL 环境）；③定义行业标准、抢话语权；④技术品牌与招聘。读这类报告，第一个问题永远是：**它在给哪条产品线铺路**。

### 十一.1 字节：工业化流水线的代表

- **SuperGPQA**（285 个研究生学科）：动机是 GPQA 只盖头部学科、长尾学科没人测。造法三层分工——**80+ 博士级专家把守题源与终审；名校众包只做"转录改写"不准出题**（前期教训：让众包直接出题，可用率只有 37%）；**7 个 LLM 当质检员**多轮试答筛题；选项扩到平均 9.67 个压猜对率。启示：公司的优势是把"专家 × 众包 × 模型质检"跑成分工明确的流水线，而不是靠一群聪明人手搓。
- **Multi-SWE-bench**（7 语言 1,632 题）：SWE-bench 只有 Python 的缺口 → 68 名外包标注 + 14 名内部工程师终审、**80% 验收准确率红线**、Docker 三态日志只认 fail-to-pass；同步发布 Multi-SWE-RL——**基准即训练基建**，评测集和 RL 数据一条产线。
- **FullStack Bench + SandboxFusion**：评测集与沙箱执行器一起开源——把"判分基建"产品化，让别人用你的尺子。
- **GPT-Fathom**：造榜之前先修尺子——同一 harness 复测所有对比模型，曝光"引用别家论文分数 = 口径不齐"的行业病。

### 十一.2 腾讯：自动生成 + 人工全量确认、judge 要自证

- **SEED-Bench**（19,242 道多模态选择题）：生成流水线 = 基础模型抽视觉信息（caption/OCR/实例描述）→ ChatGPT/GPT-4 按维度批量出题 → **3 个纯文本 LLM 试答，剔除"不看图也能答对"的题**（删 5.52%）→ 人工逐题确认答案与维度归属。判分不让模型选字母，**算每个选项的生成似然取最高**——同时规避指令跟随差异和选项位置偏置。
- **ArtifactsBench**（1,825 个前端/可视化代码任务）：评"看起来对不对"——沙箱渲染 → **按时间序列截屏**（抓动态交互）→ MLLM 裁判对着截图+源码按每题人工 checklist 打分。裁判自证动作是标准姿势：与 WebDev Arena 排名一致 94.4%、与人类专家 pairwise 一致 >90%。
- **C3-Bench**（多任务 agent 干扰测试）：User/AI/Planner/Tool/Checker 五角色多代理生成多轮任务，再由资深研究员**五轮串行人工修正把正确率从不足 60% 提到 100%**——LLM 生成的题必须配等量人工，否则就是把噪声当基准。
- **PenguinScrolls / CL-bench**：内部补测集 → 开源成公共基准的路径；CL-bench 每个任务平均挂 **63.2 条 rubric 全过才算解决**（rubric 化判分的极限形态），实测头部模型真实任务成功率不足 25%。

### 十一.3 阿里：能力短板驱动、与产品线同步发布

- **WebWalkerQA**（680 QA / 1,373 网页）：测"沿网站一路点进深层子页面"的能力——GPT-4o 合成候选 + 众包质检改写；按深度分层（单源 2-4 层、多源 2-8 层）；另发 1.4 万条未全验的 silver 数据供训练——基准与 WebAgent/DeepResearch 产品线同团队同步发布。
- **P-MMEval**（10 语言平行评测）：解决"各语言样本不平行、没法比一致性"——**数据集入选先过显著性检验**（区分不开模型的集合不收）；GPT-4o 初翻 + 专业翻译团队全量复审（各语言人工修改率 3.75%-82.5%，这个跨度本身说明机器翻译质量的语言差异）。
- **ProcessBench / CodeElo**：过程级判错（人类专家标注**最早出错步骤**，约 3,400 条竞赛题）直接服务自家 PRM 训练路线；CodeElo 用 CodeForces 真题给模型算与人类选手可比的 Elo——用"活基准"规避污染和天花板。

### 十一.4 美团 / 小米：把自家业务复杂度做成行业标尺

- **VitaBench**（美团）：外卖/到店/OTA 三个真实业务场景 → 66 个工具、300 单场景 + 100 跨场景任务、rubric 滑动窗口式评审；最强模型跨场景成功率仅 32.5%——既是基准，也是"我们这生意有多难"的对外证明。
- **Mobile-Bench**（小米）：手机 agent，832 条数据、103 个 API、三档复杂度；提出**过程性 CheckPoint 指标**——结果对但过程乱（多余动作、危险操作）也要扣分，与"只看终态"互补。

### 十一.5 公司系与学术系的五点差异（读报告时的透镜）

1. **业务锚定 vs 能力光谱**：公司系基准几乎都从产品场景或模型卖点出发；学术系追求通用覆盖。看到新基准先问"给哪条产品线铺路"。
2. **构造流水线已模板化**：LLM 批量生成 → 规则/模型自动过滤 → 多轮人工核验 → judge 报与人类一致率。大厂真正的护城河是标注预算——敢给 19K 题做全量人工确认、敢请 80 个博士。
3. **运动员兼裁判**：基准与自家模型同期发布、进自家成绩单。采信前查三件事：开源可复测吗、judge 有自证一致率吗、对比模型是同 harness 复测的吗。
4. **基准即训练基建**：评测集、沙箱、RL 数据经常是同一条产线的三个出口（Multi-SWE-RL、WebWalkerQA 的 silver 数据）——这解释了公司为什么愿意花这个钱。
5. **内部集 → 开源公共化**：先内部补测、成熟后开源抢标准定义权（PenguinScrolls、ArtifactsBench 路径）。开源那天，它就从"评估工具"变成了"生态武器"。

这些案例抽象出来的统一方法论见 §十二。

## 十二、抽象层：做 Bench/Eval 的统一方法论（五问模型）

§九、§十、§十一的全部案例，方法论上是同一件事：**把"好"变成可复现的测量**。任何评估工程——评模型、评 agent、评产品——都在按顺序回答五个问题。每个问题下面是从案例里抽出来的原则（括号里是证据锚点）。

### 问题一：测什么——把能力翻译成任务分布

1. **从"现有尺子的缺口"定义评估对象**，不从"手边有什么数据"（GPQA：头部学科之外没人测；Multi-SWE-bench：SWE-bench 只有 Python；WebWalkerQA：RAG 测不到深层遍历；ArtifactsBench：单测测不出"看起来对不对"）。缺口即定义——说不出缺口的评估项目不该开工。
2. **先建任务分类学（类型 × 难度 × 场景 × 风险），再按目标分布配额**。分布代表性优先于规模：测的是什么分布，分数就只代表什么分布。
3. **难度设计要预留 headroom 并分层**（发布时人类与模型差 5-6 倍；按人类耗时分档）——没有 headroom 的基准一年内饱和，失去分辨力就失去存在意义。

### 问题二：题从哪来——供给的三条路线与分工铁律

1. **三条供给路线**，防污染与可控性递增、成本递增：**挖存量**（真实流量/repo/业务日志 + 陡峭漏斗，产出率 2.5%-40% 是常态，要有心理预算）；**造增量**（专家原创或 LLM 合成 + 人工修正）；**搭环境**（可复位沙箱，任务在环境里长出来）。
2. **分工铁律：专家把守"定义与验收"，众包只做"转录与执行"，模型只做"初生成与初筛"**。三者错位使用必翻车——众包直接出题只有 37% 可用（SuperGPQA），LLM 生成不经人工修正正确率不足 60%（C3-Bench）。
3. **单题成本与质量是显式 trade-off**：$0（爬，6.5% 错题率）→ 几十美元（众包）→ 百美元级（专家时薪）→ 千美元级（顶级专家单题）。买的是新颖性、防污染和答案质量，没有第三条路。

### 问题三：怎么判对——判定器是评估工程的一半

1. **可判性光谱决定判定方法**（程序化 → 参考对比 → 相对比较 → 终态+轨迹 → 概率排序）；而且**把输出设计得更可判，本身就是方法论动作**——答案整数化、格式强制、选项扩容、guessproof（蒙对概率 <1%）、多选改填空。
2. **判分器要"笨而硬"**：查世界不查嘴（数据库终态/容器状态/单测，不信模型自报）；**oracle 先行**——标准解过不了判分器的题，测出来全是噪声。
3. **judge 三件套**：资格考（与人一致率 ≥ 人-人水平，通常 80-90%）、自证（与外部人类偏好体系的一致率公开，如 ArtifactsBench 对 WebDev Arena 94.4%）、去偏机制（换序重跑、控长度、换一家模型当判官）。判定器要版本化——换判官 = 换尺子，历史基线重算。
4. **答案唯一性用"独立盲复答一致"近似**；即便如此，**残余错误率 3-10% 是常态**——预算它、开纠错通道、滚动修订，别宣称零错题。用了"模型答错才收题"的对抗筛选，必须再做一轮与模型无关的正向复核（否则在富集错题）。

### 问题四：怎么算数——分数的统计学

1. **口径先于数字**：shots、温度、k 值与平均方式、judge 是谁、集合版本，全部写死在脚注。口径不齐的对比无效——要么同一 harness 复测所有对象，要么不比。
2. **方差是一等公民**：高方差集合多次采样取平均（DeepSeek 用 64 次）；能力上限报 pass@k，可靠性报 pass^k；版本比较先过显著性与 separability——**区分不开两个对象的评估集，等于没有**。
3. **诚实的报法是"报两个数"**：去污染前后、clean/full、strict/loose。单点数字都是立场，区间和双列才是测量。

### 问题五：怎么活下去——评估的生命周期运营

1. **质检流水线化**：自动过滤 → 多轮人工核验 → 对抗 exploit 探测 → 纠错回流。QA 占总预算 1/4 不夸张（OSWorld 1,800 人时里 400 小时在复查）。
2. **三防常态化**：防污染（新题/私有保留集/canary/滚动出题）、防饱和（难度储备 + 设计时就规划下一版，饱和是宿命不是意外）、防 Goodhart（定期换血 + 用在线指标校准离线分）。
3. **治理即公信力**：运动员与裁判分离、开源可复测、利益冲突提前披露——公信力只能丢一次。
4. **评估资产当基建养**：基准、沙箱、判定器、rubric 是同一条产线的四个出口（Multi-SWE-bench 与 RL 数据同源、SandboxFusion 判分器产品化）——评估投入应设计成训练与产品迭代都能复用的资产，这是它在公司里立得住的根本原因。

### 一句话版

**定义缺口 → 配分布；三路供题 → 专家把关；判定笨而硬 → judge 过资格考；口径写死 → 方差管住；三防加治理 → 当基建养。** 任何评估方案，把五问按顺序过一遍，就是一次完整的设计评审——哪一问答不上来，哪里就是这个评估的软肋。
