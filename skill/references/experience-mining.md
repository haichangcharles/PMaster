# 经历挖掘与同行感训练（Experience Mining & Peer Signal）

**适用范围：仅在 PM 求职面试准备场景使用**（梳理经历、写简历项目描述、准备"讲个项目"类问题、转岗叙事重构）。配合 interview-coach.md 的教练循环使用。

## 1. 经历挖掘访谈法（帮用户把值钱的经历挖出来）

Junior 讲不好经历的根源：**他们按时间线记忆，面试官按能力证据听**。挖掘的本质是把时间线素材重组为证据素材。

### 1.1 挖掘流程（像做用户访谈一样访谈用户本人）

1. 先让用户自由讲一遍某段经历，不打断，记录他自己强调了什么（他强调的往往不是最值钱的）
2. 用追问挖三类被 junior 埋没的金子：
   - **决策点**："这个过程中哪个决定是你拍的？当时有哪些选项？为什么选了这个？"——judgment 的证据
   - **冲突点**："有没有人反对过？谁？你怎么处理的？"——影响力的证据
   - **转折点**："有没有哪个时刻你发现原来的想法错了？"——学习能力与诚实度的证据，失败题的最佳素材
3. 每段经历追问到能回答这三个问题为止：你的独特贡献是哪一步（把"我们"拆成"我"）？有什么可量化的结果？如果重来你会改什么？
4. 输出：把每段经历重构为 STAR+复盘 格式（见 stakeholders-career.md 第 6 节 XYZ 句式），存成用户的"弹药库"

### 1.2 挖掘时的常见状况

- "我的项目太小了不值得讲" → 小项目讲判断力照样赢：面试官对"5 人小项目里的清晰决策"的评价高于"500 人大项目里的模糊参与"
- "项目失败了/被砍了" → 被砍的项目是复盘题的顶级素材，关键是归因方式：归因于己（我当时验证不足）得分，归因于人（老板乱决策）出局
- "都是执行工作，没什么决策" → 往下挖一层：执行中的微决策（怎么排的优先级、怎么处理的边界 case、怎么推动的延期资源）同样是判断力证据

## 2. 经历价值重估 rubric（成熟 PM 眼里什么值钱）

按面试官视角给经历排序。**高价值信号（从高到低）：**
1. **有取舍的决策**：主动砍需求/砍范围/说不，且讲得清代价——最稀缺，因为多数 junior 只有"做了什么"没有"没做什么"
2. **数据推翻直觉**：用证据改变了自己或团队的决定（含"用数据说服老板"）
3. **对结果的完整闭环**：定义指标 → 上线 → 复盘 → 迭代，哪怕结果不好
4. **跨职能推动**：没有权力的情况下让别的团队配合
5. **从 0 发现问题**：不是接需求，而是自己从数据/用户反馈里发现了机会

**低价值信号（junior 常误以为值钱）：** 项目规模大但个人角色模糊；"负责"了很多功能但说不出任何一个决策；纯执行的辛苦叙事（加班、赶工）；罗列使用过的工具和流程。

重估的输出：给用户的每段经历标记"主打哪个能力维度 + 适合回答哪类面试题"，组成覆盖矩阵——每个高频行为题（成功/失败/冲突/说服/取舍/资源不足交付/影响无汇报关系的人）至少要有一段对口经历，缺口就是下一步挖掘或补充的方向。

弹药库的工程标准：**6-8 个可复用核心故事**即可覆盖全部高频行为题——一段好经历通常能对口 2-3 类题（换侧重点讲，不是换故事）。每个故事备两个版本：3-5 分钟完整版（STAR + 复盘）和 60 秒电梯版（应对"简单讲讲"和被打断后的重启）。讲述时明确切分"团队整体负责 X，我个人负责的是 Y"——含糊的"我们"在面试官记分表上是 0 分。

## 3. 转岗叙事重构（工程/运营/设计 → PM）

转岗者的核心命题：**把原岗位经历翻译成 PM 能力证据**，而不是道歉式的"虽然我没做过产品"。

翻译表：
- 工程 → "我不只写代码"：主动质疑过需求合理性的时刻、提出更优方案的时刻、对用户/数据的好奇心证据。技术背景重新定位为差异化优势（方案可行性直觉、与工程对话的信用）
- 运营 → 天然离用户和数据最近：活动策划里的人群洞察、ROI 取舍、从运营反馈反推产品改进的时刻
- 设计 → 天然懂体验：从"老板要什么我画什么"里挖出"我基于用户逻辑反对过什么"；补商业与数据短板的证据
- 通用句式：不说"我没有 PM 经验"，说"我在 X 岗位上已经在做 PM 工作的 Y 部分，比如 [具体事例]，现在想把 Z 部分补全"

**转岗动机题的标准结构**：具体触发事件（不是"我喜欢和人打交道"）→ 已做的验证行动（转岗前主动做过的产品性工作，这是诚意的唯一证据）→ 原岗位带来的独特优势。

## 4. 同行感训练（被面试官看成同行的信号系统）

面试官在前 5 分钟就会给候选人贴标签："背书的学生"还是"能一起干活的同行"。同行感来自五个可训练的信号：

1. **拿到题先澄清**："这个产品的目标是增长还是变现？面向什么平台？"——同行的第一反应是定义问题，学生的第一反应是给答案
2. **主动交代取舍**："我先聚焦 X 人群，Y 人群这次放弃，因为……"——同行知道资源有限，学生想面面俱到
3. **给结论标注置信度**："这块我有数据支撑；那块只是假设，需要验证"——同行区分知道和猜测，学生把所有话说得同样确定
4. **有理有据地反驳面试官**：面试官抛出质疑时，同行会说"这个担心有道理，但我认为不成立，因为……"——敢反驳且反驳有据，是最强的同行信号（顺从地立刻改口是最强的学生信号）
5. **说行话但不堆行话**：准确使用"灰度""护栏指标""机制假设"，但每个术语都能用大白话解释——堆砌术语反而暴露心虚

训练方法：模拟面试中把这五个信号列为隐藏观察项，反馈时逐个指出"哪个瞬间你像同行、哪个瞬间露怯了"。

## 5. 问题的潜台词速查（面试官到底在问什么）

| 面试官问的 | 实际在考的 | 高分策略 |
|-----------|-----------|---------|
| 讲一个你最有成就感的项目 | 你的能力上限 + 你认为什么值得骄傲（价值观）| 选"判断力密度"最高的，不是规模最大的 |
| 讲一个失败的项目 | 归因方式 + 复盘能力，不是失败本身 | 归因于己的具体决策 + 讲清楚现在会怎么做 |
| 为什么离开上家 | 稳定性风险 + 成熟度 | 向前看的理由（想要什么）优于向后看的抱怨（讨厌什么）|
| 你最大的缺点 | 自我认知的诚实度 | 真实但非致命的缺点 + 正在做的具体改进（"我太追求完美"这类伪缺点直接扣分）|
| 如何看待我们的产品 | 诚意（做没做功课）+ 判断力 | 具体的观察 + 一个有依据的改进假设 + 承认信息有限 |
| 为什么选我们公司 | 匹配度 + 你会不会很快跑掉 | 和自己经历/目标的具体连接，不是商业互吹 |
| 薪资期望 | 谈判开局 | 给有依据的区间 + 表达对机会本身的权重 |
| 你还有什么问题问我 | 关注点层次 + 最后的判断力展示 | 见 pm-job-interview-prep.md 第 7 节 |
| （追问）为什么？为什么？为什么？ | 判断的地基深度 | 每层都能给出证据或假设，到达真实边界时坦率说"这是我的假设，还没验证" |
| （质疑你的方案）| 不是方案错了，是测你被压后的反应 | 有依据地坚持或有理由地更新，都得分；无理由的立刻投降，出局 |
